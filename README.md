# Joint learning

## Project structure

All the modelling scripts are in the `model` folder. The `model` folder contains:
- `basicmodel.ipynb`: The main file to see the work in the project. Contains plots and explanations.
- `figures`: Contains some of the modelling and data visualizations.
- `scripts`: Contains files with most of the code. Specifically:
	- `data_functions.py`: Functions to deal with the experimental data, e.g., get it, wrangle it, etc.
	- `model_free_analysis.py`: Functions to run the logistic regression on experimental data.
	- `plotting_functions.py`: Functions to plot the data and modelling results.
	- `simulation_functions.py`: Functions to simulate fake datasets from the weight model and idealized Bayesian model.
	- `weight_model_fit`: Functions to fit the weight model to experimental data.

The folder `server_jobs` contains files to run the weight model fit on a SLURM scheduler.

## How to fit the weight model locally

The following libraries are needed:

- Pandas
- Numpy
- Scipy
- pymc (versions 3, 4, or 5)
- Arviz 

The first step is to change the file `model/scripts/weight_model_fit.py` to tell it where the data is located. Go to the end of the file and change the needed bit:

```python
if __name__=='__main__':
    
    get_and_fit_data(
        participant_exclusion=True, 
        method='hmc',
        fit_kwargs={
            'draws': 1000,
            'tune': 1000,
            'chains': 4
        },
        model_kwargs={
            'hierarchicallearningweights': False,
            'softmax_choice': True
        },
        datapath= GIVE RELATIVE PATH TO DATA FILE
    )
```

Since the project is organized as a package, please go to the 'model' folder and run:

```bash
python -m scripts.weight_model_fit
```

This should start the fitting!

# Run via ClickHouse server

Steps:
- Make sure Docker is working fine
- Start ClickHouse server via Docker image
    - Pull ClickHouse image with `docker pull clickhouse/clickhouse-server` from [this page](https://hub.docker.com/r/clickhouse/clickhouse-server/).
    - Run server with :
		```
		docker run -d -v $(realpath ./ch_data):<absolute/path/to/results/folder> --network=host --name some-clickhouse-server --ulimit nofile=262144:262144 clickhouse/clickhouse-server
		```
	- This should start a ClickHouse server. Description of command step-by-step (generated by gpt-4):
		- `docker run`:
			- This command is used to create and run a new container from a Docker image docker run command runs a command in a new container, pulling the image if needed and starting the container","pub_date":null}}.
		- `-d`:
			- This option runs the container in the background and prints the container ID. This is known as "detached mode", -d Run container in background and print container ID","pub_date":null}}`.
		- `-v $(realpath ./ch_data):<absolute/path/to/results/folder`:
			- This option binds the local directory ./ch_data (after resolving its real path using realpath) to the directory /var/lib/clickhouse/ in the Docker container. This allows the container to access and manipulate data in the specified local directory, essentially using it as a data volume.
			- NOTE: Make sure you have writing auth for the results folder, or an error will be raised.
		- `--network=host`:
			- This option connects the container to the host network, meaning the container can access network resources just as the host machine does.
		- `--name some-clickhouse-server`:
			- This assigns the name some-clickhouse-server to the container. This is useful for managing containers later, for example when stopping or starting the container.
		- `--ulimit nofile=262144:262144`:
			- This sets a limit on the number of open file descriptors for the container. The format is nofile=<soft limit>:<hard limit>, and in this case, both the soft and hard limits are set to 262144.
		- `clickhouse/clickhouse-server`:
			- This is the Docker image that the container will be based on. In this case, it's the image for ClickHouse server, which is a fast open-source column-oriented database management system.
	- You can check that the code is running fine with the following command, which prints the install version of ClickHouse: 
		```
		echo 'SELECT version()' | curl 'http://localhost:8123/' --data-binary @-
		```
- When done, stop the server with:
    - `docker stop <servername>`
- And at the end of the sampling, remove the container with:
    - `docker rm <servername>`
